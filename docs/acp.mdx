`@e2e-dev/acp` runs `agent.act` and `agent.assert` on a coding agent you
already use, over the [Agent Client Protocol](https://agentclientprotocol.com)
(ACP): Claude Code, Codex, Cursor, or any other agent with an ACP mode. The
agent signs in the way it does on its own, with its CLI login or its own API
key, so e2e needs no model provider of its own.

The agent gets the built-in agent's own action tools for the verbs your
target's engine supports, with its rules for them, plus `complete_step`. Every
action goes through the runner, which authorizes, counts, and records it, so
steps replay from the [cache](/cache) without the agent.

## Install and configure

<CodeGroup>
```bash npm
npm install -D @e2e-dev/acp
```

```bash pnpm
pnpm add -D @e2e-dev/acp
```

```bash bun
bun add -d @e2e-dev/acp
```
</CodeGroup>

`command` and `args` start the agent in ACP mode on stdio:

<Tabs>
  <Tab title="Claude Code">
Install Zed's ACP adapter for Claude Code (`@agentclientprotocol/claude-agent-acp`) beside it.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { acpExecutor } from '@e2e-dev/acp';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: {
    default: {
      executor: acpExecutor({
        command: 'npx',
        args: ['claude-agent-acp'],
        model: 'sonnet',
        // Claude adapter options: no built-in tools, no user or project settings.
        sessionMeta: { claudeCode: { options: { tools: [], settingSources: [], strictMcpConfig: true, persistSession: false } } },
      }),
    },
  },
} satisfies E2EConfig;
```
  </Tab>
  <Tab title="Codex">
Install the Codex ACP adapter (`@agentclientprotocol/codex-acp`) beside it.

Codex loads your own MCP servers and plugins into every session, and runs
web search and subagents without asking permission. `CODEX_CONFIG` turns
them off for these sessions only; the adapter merges it over your Codex
config, which stays untouched. Name each MCP server and plugin your config
declares.

```ts title="e2e.config.ts"
executor: acpExecutor({
  command: 'npx',
  args: ['codex-acp'],
  model: 'gpt-6-luna',
  mode: 'read-only',
  env: {
    CODEX_CONFIG: JSON.stringify({
      web_search: 'disabled',
      tools: { web_search: false },
      features: { multi_agent: false },
      // One entry per [mcp_servers.<name>] and plugin in ~/.codex/config.toml.
      mcp_servers: { playwright: { enabled: false } },
      plugins: { 'browser-use': { enabled: false } },
    }),
  },
}),
```
  </Tab>

Tests stay plain natural language:

```ts title="tests/todos.e2e.ts"
import { test, expect } from 'e2e';

test('adds a todo', async ({ app, screen, agent }) => {
  await app.open('/todos');
  await agent.act('Add a todo named Buy coffee.');
  await expect(screen.getByText('Buy coffee')).toBeVisible();
  await agent.assert('The todo list contains Buy coffee.');
});
```

| Option | What it does |
| --- | --- |
| `command`, `args` | Start the agent in ACP mode on stdio. |
| `env` | Variables added to the agent's environment. |
| `model` | A value of the session's model option. The session fails to start when the agent does not offer it, and the error lists what it does offer. Omitted, the agent's default runs. |
| `mode` | A session mode to select, such as Codex's `read-only`. |
| `sessionMeta` | `_meta` for `session/new`: options only one agent's adapter reads. |
| `system` | Appended to the rules the agent gets with the first step. |

## How a test runs

One agent session serves one test attempt. The first agent step that the
cache cannot replay starts it, every later step of the test is one more
message in the same conversation, and the session closes when the attempt
ends. Each message carries the step, its non-secret params, the steps
completed so far, and the current screen. Action results report what
changed on screen since, as they do for the built-in agent, and a
`screenshot` reaches the agent as an image.

The session lists its tools once. Two of them depend on the step:
`type_secret` comes with a step that declares secrets, and `screenshot` goes
once a secret was filled in the attempt. A step's message names the ones it
does not offer, and a call of one says why.

The tools reach the agent as an MCP server that the test worker serves on
`127.0.0.1`, on an ephemeral port and a random path. The agent process
starts in your project, so a locally installed adapter resolves, but its
session opens in an empty temporary directory, and e2e advertises no file
system or terminal access to it. When the agent asks permission for a tool, calls of the step
tools are allowed and anything else is rejected.

An assertion gets the same session and tools, but an action during an
assertion is refused; `observe`, `screenshot`, and scrolling still work. The agent concludes it with `complete_step`, and a
`failed` verdict fails the step with `ASSERTION_FAILED`.

## Secrets

A secret in the params reaches the agent by name only. The agent fills it
with `type_secret`, and the runner authorizes the fill and types the value
itself, the same as for the built-in agent.

## Limits

- The step tools should be the agent's only tools, but ACP has no standard
  switch for that. e2e rejects every other tool the agent asks permission
  for, and an agent can still run its own tools that never ask: built-in
  file and search tools, web search, subagents, and the MCP servers and
  plugins from your own config. Each agent turns them off its own way:
  Claude Code through `sessionMeta`, Codex through `CODEX_CONFIG`, as the
  examples above show. In our runs, Cursor's ACP mode used only the step tools with no options.
  Without them, an agent may reach for a browser tool of its own instead of
  the step's `tap`, and a step it should have done fails.
- Model requests are not reported over ACP. Each prompt turn counts as one
  model call against `maxModelCalls`, with the turn's tokens and cost when
  the agent reports them; `maxSteps` and the step timeout bound the turn.
- `waitFor` and `extract` still use the built-in judgments and need the
  agents entry's `model`.
